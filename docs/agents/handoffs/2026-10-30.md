## Certificate work in this checkpoint

`Api/CertificateInspection.cs` adds an in-memory .NET 10 PFX inspection helper. It loads keys
with EphemeralKeySet, disposes certificate/key handles and returns public metadata only.
Limits: 512 KiB PFX; password 1024 UTF-8 bytes/no NUL; one key; 16 certificates;
MAC/individual KDF 300000 iterations; total KDF 1000000; 1-32 requested hosts; 128 DNS/IP
alternative names; subject/issuer display capped at 1024 UTF-16 units without splitting a surrogate.
It normalizes DNS/IDNA/canonical IP input, uses SAN matching with common-name fallback disabled,
compares key public components, reports validity/CA/EKU/key-strength/expiry warnings and builds
the chain using the current Windows identity with certificate downloads disabled and revocation
explicitly NotChecked. Bundled roots are not made trusted. Inspection is not install/activation
approval, client trust, complete TLS compatibility or revocation verification. RSA/ECDSA fixtures
passed; DSA and other key/provider compatibility still need acceptance. No private-key export exists.

Primary API reference: [Microsoft Pkcs12LoaderLimits](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.pkcs12loaderlimits?view=net-10.0).
The stable [.NET 10 source](https://raw.githubusercontent.com/dotnet/runtime/v10.0.0/src/libraries/Common/src/System/Security/Cryptography/X509Certificates/Pkcs12LoaderLimits.cs)
and installed 10.0.13 reference XML confirmed these APIs; Learn pages can mix in .NET 11 preview
package banners, so compile against the actual stable target. Do not use DangerousNoLimits.
