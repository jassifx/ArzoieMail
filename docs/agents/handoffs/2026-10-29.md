## Implemented on this branch

- Typed native/REST/panel server settings: the first 60 fields in protocols, SMTP, IMAP, POP3, Auto-ban,
  greylisting, performance, general and existing antivirus passed initial VM validation. Four
  subsequent passwordhash fields (algorithm, memoryKiB, iterations, autoUpgrade) add cross-field
  validation and dependency guards; they passed subsequent Compact VM runs. Nine logging fields
  then brought the allowlist to 73 fields in 11 sections, with merged checked updates of shared
  flag bits and preserved omitted bits. The full 736-native-assertion run passed. Defaults are unchanged.
  Numeric patch preconditions use the caller's expected value directly, rather than rereading
  a potentially changed cache value. Server-only, bounded explicit schema,
  expected-value patches and confirmation/reload/restart guidance. No arbitrary properties,
  SQL, executable paths or secret getters. Both greylisting retention values use **hours**.
- PropertySet checked batches use one leased transaction connection, guarded bound updates,
  checked readback and cache publication only after commit; notifications follow unlocking.
  Numeric cache values are atomic; strings and map publication have locks. Legacy writers share
  the write mutex, but legacy setters are not themselves checked transactions. Protocol threads
  do not obtain simultaneous multi-property snapshots. The later transaction-pool correction
  retires uncertain physical clients after failed/exceptional begin/commit/rollback, restores
  capacity with an unopened replacement and opens it before any SQL borrower. Unsupported
  transactions return 412 (MySQL capability requires all tables InnoDB). Shared pure helper
  fault regressions passed in the VM; real provider outages/acknowledgement loss and concurrent
  legacy-tool acceptance remain pending.
- Typed SURBL, blocked-attachment and trusted incoming-relay CRUD, optimistic loaded-object
  checks, paging metadata, validation, cache refresh and modern panel forms. Current adapters
  bound IDs to signed 32-bit legacy persistence capacity. Blocked attachments have a bigint table
  but legacy narrowing persistence: do not claim full high-ID acceptance. Collections still scan
  metadata and do not have transactional cross-COM compare-and-swap protection.
- Mailbox self-service native/REST/panel: own profile, signature, forwarding/replies, bounded
  mailbox rules and password change. Native identity derives parents; caller-supplied ownership
  IDs are rejected. AD password changes are unavailable. Current-password proof and fresh hash
  verification precede password changes; the browser session is removed after success. Passwords
  never enter response objects. Self-service account writes update only permitted columns, with
  password/role/active/directory/address guards, rather than saving a stale full account object.
  Reply-history notification is deferred until a successful guarded self-service save/readback;
  other legacy saves retain their previous BO behavior. Signature source remains inert.
  Own rules keep existing unsupported-action restrictions.
  Self-service passed the subsequent full Compact VM/browser run, but final four-backend and
  production security acceptance remain pending.
- IP security ranges: 21 explicit fields including IPv4/IPv6 interval, priority, protocol/relay/
  authentication/TLS/spam/virus/expiry settings and a transient unauthenticated-relay acknowledgement.
  New ranges deny connections. Server-only CRUD and native matching inspection; independent
  management remains available for recovery. Explicit acknowledgement preserves intentional trusted
  relays without silently enabling unsafe relay. Native tests exercise actual SMTP denial/recovery,
