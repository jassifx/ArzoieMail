## Architecture revision and implementation start - 2026-10-26

The maintainer authorized Phase 1b and requested removal of COM from the new panel/backend.
The current design is ASP.NET Core / .NET 10 with a restricted local native management channel.
Keep COM independently for existing tools and scripts. See
[architecture](../../management-api-architecture.md) and the updated requirements; this revision
supersedes earlier PHP/COM implementation notes below. Work is on
`feature/webadmin-rest-foundation`; follow its pull request for current review/CI status.
The first implementation slice is a preview, not the completed phase or installer replacement.

**Review gate:** after submitting each PR, wait for the maintainer's confirmation before the
next task/phase/PR. Continue monitoring and fixing the submitted PR's CI within its scope.
Green checks are not permission to merge or to continue subsequent work.

### Foundation implementation

- ASP.NET Core REST/session security and Bootstrap panel are under `source/Management/Api`.
- Native pipe dispatch and shared credential validation are under `Server/Common/Management`.
  COM remains an independent compatibility adapter for existing desktop tools and scripts.
- Implemented preview operations cover identity, status, domain inspection, spam settings,
  DNSBL CRUD, saved SpamAssassin connection testing and SPF/DKIM/DMARC DNS advice.
- Regression sources are in `test/RegressionTests/Management`; scripts under `build/` enforce
  VM-only execution. CI runs the new suites alongside all three installed-database jobs.
- Native/API Release builds pass. VM security, deterministic DNS, native authorization/parser,
  anti-squatting and browser/mobile tests have run successfully. Check the PR for final counts
  and the existing regression suite result before merging.
- The VM baseline uses schema 5713; current server builds require 5714. Testing uses an isolated
  upgrade with database/INI/executable restoration; the full suite additionally uses a temporary
  VM checkpoint. Do not deploy the new executable against the old schema and mistake the
  resulting initialization failure for a pipe/network problem.
- **All runtime tests and previews must run in the VM or CI.** Host editing, static inspection
  and compilation are allowed; the local preview was stopped when the maintainer clarified this.
- Remaining work includes complete administration-page parity, final API hosting/installer
  provisioning, SpamAssassin engine packaging, richer DNS guidance and full release acceptance.
  The existing PHP application has not been switched over by the installer.
