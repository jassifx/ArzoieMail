## SQL Server slice

See [SQL Server deployment](../../sql-server.md) and [ROADMAP](../../../ROADMAP.md).
The implementation requires x64 Microsoft OLE DB 19 (`MSOLEDBSQL19`), SQL Server 2019+,
TCP and required encryption. No fallback to SQLOLEDB, SQLNCLI or OLE DB 18. Certificate
validation defaults on; Strict mode is available for compatible SQL Server 2022+ deployments.
An explicit certificate-trust exception is documented for isolated testing, not a production
recommendation. SQL Server Compact is unaffected.

Security options flow through both service connections and existing DBSetup operations.
Connection values are quoted and ADO data-type compatibility is explicit. DBSetup exposes a
fixed TCP port or 0 for instance/default discovery. Installer preflight blocks MSSQL upgrades
missing the x64 driver or still selecting a legacy provider before replacing files. The optional
external driver and its x86/x64 VC runtime prerequisites are not bundled by this PR; prepare them
before an offline upgrade. Follow the guide for trusted certificates and older engine migration.

ADO remains a supported native database wrapper, independent of the legacy hMailServer management
COM API. This does not add COM or direct SQL to the replacement REST/web backend.

## Repeatable fixtures and gotchas

`build/provision-mssql-test.ps1 -DisposableEnvironment` and
`build/test-mssql-connection.ps1` are VM/CI-only. They provision a dedicated Express instance,
exercise TLS/auth/schema behavior, then leave the service on its dedicated SQL database for tests.
They are not production deployment scripts. The OLE DB MSI has a pinned hash; downloaded
Microsoft installers are signature checked. Never run them on the development host.

ADO needs `Trust Server Certificate=True/False`, not yes/no. Use `Data Source` when quoting
endpoints. Require actual certificate errors in negative tests so a malformed connection string
cannot count as success. Certificate CSP keys can be wrapped as RSACng; check the exact filename
and key provider before granting access. The old VM's installed database-creation scripts were
5713; use the current 5714 scripts with the new native executable. See gotchas.md.
